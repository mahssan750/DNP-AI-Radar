====================================================================
 DNP-Ai-Radar - How to run it
====================================================================

This is your internal, self-hosted copy. It has two parts that run at
the same time:

  - the dashboard you look at, in a web browser
  - a background worker that quietly asks the AI engines your questions
    and saves the answers

Both start with one command.


--------------------------------------------------------------------
 EVERY DAY - just start it
--------------------------------------------------------------------

  1. Open PowerShell
  2. Type these two lines:

        cd C:\Users\moham\Projects\DNP-Ai-Radar
        pnpm dev

  3. Leave that window open, and go to:

        http://localhost:3000

To stop it, click the PowerShell window and press Ctrl + C.
Closing the window also stops it.

IMPORTANT - only ever run ONE copy at a time. The app only accepts
sign-ins at localhost:3000. If a second copy starts, it now refuses to
start rather than quietly moving to another port, because a copy on a
different port cannot log you in.


--------------------------------------------------------------------
 MOVE THIS COPY TO ANOTHER WINDOWS COMPUTER
--------------------------------------------------------------------

The portable export includes the current accounts, brands, collected data,
settings, API credentials, and app secrets. It encrypts all of them with a
transfer password before writing the bundle.

On this computer, open PowerShell in the project folder and run:

        pnpm portable:export

Choose a transfer password of at least 12 characters. The finished folder is
written under:

        portable-output

Copy that whole dated folder to the new computer, install and start Docker
Desktop there, then double-click INSTALL-DNP-AI-RADAR.cmd. Enter the transfer
password when asked. After the first setup completes, use
START-DNP-AI-RADAR.cmd and STOP-DNP-AI-RADAR.cmd in the installed folder.

Keep the transfer password separate from the bundle. Anyone who has both can
access the copied data and provider credentials.


--------------------------------------------------------------------
 STILL TO DO - add your AI provider keys
--------------------------------------------------------------------

Until you do this, the dashboard works and you can sign in, but no data
is collected and "Analyze brand" fails, because the app has nothing to
ask the AI engines with.

Get your keys here (they are shown once, at the moment you create them,
so save them somewhere safe):

    OpenAI     https://platform.openai.com/api-keys
    Anthropic  https://console.anthropic.com/settings/keys

Open BOTH of these files in Notepad:

    C:\Users\moham\Projects\DNP-Ai-Radar\.env
    C:\Users\moham\Projects\DNP-Ai-Radar\apps\web\.env

In each, replace these two lines with your real keys:

    OPENAI_API_KEY=REPLACE_WITH_YOUR_OPENAI_KEY
    ANTHROPIC_API_KEY=REPLACE_WITH_YOUR_ANTHROPIC_KEY

Save, then stop the app (Ctrl + C) and start it again.

These keys cost money per question asked. That is exactly why the run
frequency and pause controls were added - see below.


--------------------------------------------------------------------
 KEEP THESE FILES PRIVATE
--------------------------------------------------------------------

The two .env files hold your database password, two app secrets, and
your API keys. Never paste their contents into a chat, an email, a
screenshot, or a support ticket. They are excluded from GitHub on
purpose, so they are never uploaded.

If the contents are ever seen by anyone else, treat all of it as
compromised:

  - Change the PostgreSQL password (see "Changing the database
    password" below), then run .\setup-database.ps1 again.
  - Ask Claude to regenerate BETTER_AUTH_SECRET and ELMO_ENCRYPTION_KEY.
    Changing BETTER_AUTH_SECRET signs everyone out; changing
    ELMO_ENCRYPTION_KEY means any provider keys the app has stored must
    be entered again.
  - Delete the exposed API keys in the OpenAI and Anthropic dashboards
    and create new ones.


--------------------------------------------------------------------
 WHERE THE NEW FEATURES ARE
--------------------------------------------------------------------

Run frequency, and pause / resume
    Left sidebar -> Settings -> Brand, then scroll to the "Schedule"
    card at the bottom.

    Choose how often the questions are asked: every day, every 2, 3, 5,
    7, 14 or 30 days, or type your own number of days. "Pause tracking"
    stops all AI calls, and their cost, straight away. Nothing already
    collected is lost, and "Resume" picks it up again.

    Only an administrator account sees these controls. The first
    account you create is the administrator.

    While a brand is paused, a yellow bar appears across the top of
    every one of its pages, so it can never be left off by accident.

Statistics
    Left sidebar -> Statistics.

    Total questions asked in the period and since the very beginning,
    how often your brand was mentioned, how many days had activity, the
    typical gap between runs, a bar chart per day, and tables broken
    down by AI engine and by question.

    Drag the slider at the top to change the period - anything from one
    day to a full year. The period is stored in the browser address, so
    you can bookmark a view or send it to a colleague.

    The "typical gap" figure is your proof that the run frequency
    setting is working. Set it to every 3 days and, after a week or so,
    that figure should read about 3.

Exports
    "CSV" buttons sit on every table and on the daily chart, and also on
    Top Cited Domains and Top Cited URLs on the Citations page. They
    download a file you can open in Excel.

    "Print / Save as PDF" is at the top right of the Statistics page. In
    the print window that opens, choose "Save as PDF" as the printer.

    "PNG" and "Export (PNG)" download a picture of a chart, for pasting
    into a slide or document.


--------------------------------------------------------------------
 IF SOMETHING GOES WRONG
--------------------------------------------------------------------

"Port 3000 is already in use" and the app refuses to start
      Another copy is already running. Find its PowerShell window and
      press Ctrl + C. To find it if you cannot:

          Get-NetTCPConnection -LocalPort 3000 -State Listen |
            ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

"Invalid origin: http://localhost:3004" in the PowerShell window
      An older version let the app drift to a spare port when 3000 was
      busy, which broke sign-in. It now refuses to start instead. If you
      still see this, you are running an old copy - stop everything and
      start again.

"Brand analysis failed. Please try again."
      Almost always the API keys are still the placeholder text. See
      "Still to do" above. The line
          [website-excerpt] all sources failed
      in the PowerShell window is a separate, harmless warning - it just
      means the website blocked the content fetch, and the analysis
      carries on without it.

"pnpm is not recognised"
      Open a fresh PowerShell window. If it still fails, run:
          npm install -g pnpm@11.18.0

"The filename, directory name, or volume label syntax is incorrect"
      The project has been moved to a folder whose path contains a
      space. Move it back to a path without spaces.

"password authentication failed for user postgres"
      The password inside the DATABASE_URL line no longer matches.
      Run .\setup-database.ps1 again to rewrite it.

"relation ... does not exist"
      The database tables are missing. Run:
          cd packages\lib
          pnpm exec drizzle-kit migrate

The dashboard loads but stays empty
      Normal at first. The worker has to ask the AI engines before
      there is anything to show. Check that your API keys are real, that
      the brand is not paused, and that its questions are switched on
      under Settings -> Prompts.


--------------------------------------------------------------------
 CHANGING THE DATABASE PASSWORD
--------------------------------------------------------------------

  1. Stop the app (Ctrl + C).
  2. Run, and enter the current password when asked:

        & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -h localhost -p 5432 -d postgres

  3. At the prompt that appears, type (with your own new password):

        ALTER USER postgres WITH PASSWORD 'your-new-password';
        \q

  4. Run .\setup-database.ps1 and give it the new password. It rewrites
     the connection line in both .env files.
  5. Start the app again with pnpm dev.

 STARTING COMPLETELY FRESH
--------------------------------------------------------------------

This erases every account, brand and collected result. There is no
undo. Only do it deliberately.

    cd C:\Users\moham\Projects\DNP-Ai-Radar

    .\setup-database.ps1        # answer yes if it offers to reset

    cd ..\..
    pnpm dev

Then create your administrator account again at localhost:3000.


--------------------------------------------------------------------
 HOW THIS MACHINE WAS SET UP
--------------------------------------------------------------------

Written down in case you ever move the project or set it up elsewhere.

  Project location
      C:\Users\moham\Projects\DNP-Ai-Radar
      The path must not contain spaces - the tool that packages the
      code fails on them with a confusing error.

  pnpm (the command that installs and starts everything)
      npm install -g pnpm@11.18.0

  Settings files
      .env and apps\web\.env, holding generated secret values.
      Both are excluded from GitHub.

  Database
      PostgreSQL 18 on port 5432, database name "dnp_ai_radar".
      Created by setup-database.ps1, which asks for your PostgreSQL
      password without showing or storing it. Note this machine also
      runs PostgreSQL 17 on port 5433; the app does not use it.

  Parts the app is built from
      pnpm install

  Database tables
      cd packages\lib
      pnpm exec drizzle-kit migrate
